## Retained Design Decisions

- Profiles are private per CLI/account. Only the selected profile and its CLI's
  shared history mount in an assistant container. Native homes remain untouched
  unless the user explicitly selects legacy mode or invokes the importer.
- History remains native to each CLI. Shared discovery does not bypass provider
  ownership rules, convert conversations or support concurrent editing of one
  conversation. Distinct conversations can use separate CX instances.
- The workspace stays `/workspace/main`, `cx-external` and `remote`, with
  persistent environments and explicit writable file/directory mounts.
- Both adapters use the existing SSH shell, command tracker, MCP socket and
  Slurm readiness hook. Authentication is manual; uncertain commands are never
  automatically replayed. Remote mounts stay on the original login host/path.
- Sessions has its own blue pane. SSH is green. Local interactive managed
  sessions use the same renderer without invoking SSH. Enter queues handoff
  until a clean native assistant exit instead of injecting a quit command.
- Installed, portable and custom data-root behavior remain supported. Runtime
  data and credentials are excluded from source distributions.

## Historical Workflow and Model Guidance

Implementation branches originally started from `origin/v2`, PRs targeted `v2`,
and the final integration PR targeted `main`. That workflow is complete.
Current work does not need another integration branch or a v2-to-main PR.

The implementation recommendation was `gpt-6.1-sol`, with high reasoning for
account isolation and terminal/concurrency work and medium reasoning for bounded
adapter changes. It was an engineering recommendation, not a measured cost or
current pricing claim. Use focused tasks and appropriate checks; do not infer
subscription/API cost from a conversation's cumulative token count.

## Validation Records and Limits

[CX-2 validation](CX2-VALIDATION.md) and [CX-7 validation](CX7-VALIDATION.md)
retain their implementation-time checks, skips and live gates. The source merge
records delivered code; it does not establish untested provider login/refresh,
Windows Terminal, Docker/SSHFS, or site-specific scheduler behavior.

Continue to report actual checks and limitations in new PRs. Use fixtures for
routine work. Live authentication, remote writes and allocations require the
relevant user authorization; a validation checklist does not grant it.
