# v2 Multi-CLI and Account Integration

`v2` is the integration branch for adding Claude Code and named account profiles
alongside Codex. `main` remains the stable/default branch. The branch name does
not assign a release version or change `VERSION`.

## Branch and PR Workflow

Start every implementation branch from the latest remote integration head:

```bash
git fetch origin
git switch --no-track -c feature/cx-1-account-profiles origin/v2
# Implement, test, and commit the focused change.
git push -u origin feature/cx-1-account-profiles
gh pr create --base v2
```

Bring in subsequent `origin/v2` changes before final validation if the integration
branch advances. Review and merge implementation PRs into `v2`, then create the
next implementation branch from its new head. Do not base new work on a stale
feature branch or direct implementation PRs at `main`.

CI runs on pushes to `main` and `v2` and on pull requests. Keep the required
status-check name `Offline checks` unchanged. The default branch remains `main`;
GitHub will not select `v2` automatically, so check each PR's base explicitly.

## Two Implementation Issues

Use these exact issue titles to keep the work in two coherent units. Each issue
includes implementation, regression tests, and related documentation; no separate
tracking epic or documentation issue is needed.

Use `CX-<GitHub issue number>` as the shorthand ID and lowercase it in branch
names: `feature/cx-1-account-profiles` or `feature/cx-2-claude-parity`. Focused
follow-up branches can use another descriptive suffix with the same issue ID.
Link PRs to the corresponding GitHub issue; the shorthand is a naming convention,
not a separate issue tracker.

Issue 1 establishes agent adapters, a single image with both CLIs, fresh private

Issue 2 depends on issue 1 and completes shared SSH/MCP/Slurm integration,
terminal behavior, packaging, user/developer documentation, and the final
integration test matrix.

## Accepted Behavior

- Show a combined CLI/account picker on every interactive launch unless the
  user selects a complete pair explicitly. Filter by CLI when only one is given.
- Support `--agent codex|claude`, `--account NAME`, account list/add/default,
  selected-account login/status/logout, noninteractive `exec`, and native resume.
  Keep native `--profile` separate and respect the `--` forwarding boundary.
- Noninteractive use requires explicit selection or an automation default;
  help/build/doctor/Slurm setup must not prompt for an account.
- Store fresh profiles under cx-managed installed/portable data with
  `CX_DATA_HOME` support. Leave existing CLI homes untouched; retain explicit
  `CX_CODEX_HOME` compatibility as documented legacy mode.
- Keep credentials, settings, plugins, and caches private to the selected
  account. Mount only that profile plus the shared history for its CLI.
  Credential refresh must support atomic replacement. Do not expose secrets in
  arguments, metadata, output, or unrelated host authentication variables.
- Allow different accounts to run distinct conversations concurrently. Share
  browse/resume history among Codex accounts and among Claude accounts, using
  the selected account to resume. Do not convert conversations between CLIs,
  rewrite attribution, bypass provider restrictions, or promise simultaneous
  editing of the same conversation.
- Keep both clients at `/workspace`, with `main/`, `cx-external/`, and `remote/`.
  Load Claude project instructions/settings/MCP from `main` without editing the
  project. Preserve managed restrictions, Codex behavior, and native CLI prompts.
- Match current cx autonomy inside Docker. Use Claude permission bypass only
  as a non-root user. Keep package-change and Slurm authorization instructions.
- Preserve file/directory mounts, ignore masks, environments, persistent remote
  shell state, manual authentication, command tracking, polling, cancellation,
  bounded output, and unknown-outcome handling. Never replay uncertain commands.
- Reuse the existing MCP adapter and Slurm bridge/hook. Preserve other user MCP
  servers, reserved-name checks, and `--no-ssh-mcp` fallback.
- Keep SSH green and assistant blue, showing agent/account in the bar. Preserve
  scroll, selection, paste, styles, resize, and separate saved screens.

## Model and Token Budget Guidance

Recommendations are engineering judgments, not benchmarked implementation costs.
Sol is the default because these two grouped issues involve cross-component
coding and consequential account/transport behavior. Use standard processing
when available; avoid Fast/Ultrafast and maximum reasoning by default.

Use `gpt-6.1-terra` at medium reasoning for bounded documentation-only work
after behavior is established. Do not use it as the sole reviewer of credential
isolation or SSH command lifecycle changes. Escalate reasoning for a specific
reproduced blocker rather than restarting the entire issue with a larger model.

Keep each implementation task focused. Read relevant files, bound tool output,
run targeted checks after edits, and run the full matrix at integration gates.
Use a concise verified handoff when starting a different task. Do not estimate
cost from cumulative conversation tokens or assume cached input is free.

Guidance checked on 2026-11-15. Model availability and billing vary by account;
API prices are not a direct conversion to subscription allowance. Recheck the
[Sol model guide](https://developers.openai.com/api/docs/models/gpt-6.1-sol),
[Terra model guide](https://developers.openai.com/api/docs/models/gpt-6.1-terra),
and [Codex pricing](https://developers.openai.com/codex/pricing) before assignment.

## Final Integration Gate

After both issues are implemented and reviewed into `v2`, open one final PR:

```bash
gh pr create --base main --head v2 --title "Integrate Claude Code and Account Profiles"
```

Merge only after all offline suites pass and documented live checks establish
login persistence, account isolation, shared resume, concurrent distinct
conversations, Docker mounts, terminal behavior, SSH/MCP, and explicitly
authorized CPU/GPU allocations for both agents. Include tested CLI versions,
skips, limitations, migration steps, and image rebuild instructions. A missing
live parity check remains an open release gate, not a claimed pass.

Source archives and installed/portable editions must include intended new files
without credentials, histories, environments, or private notes. No cross-CLI
history conversion, cloud-provider authentication, analytics, automatic account
rotation, publication, or final merge is authorized by creating this branch.
